# Logical query planning

Vail lowers a lazy TableIR action into a DataFusion logical tree, runs DataFusion's logical optimizer, and uses its physical planner to produce an executable tree. `NativeTable.logical_plan()` displays the optimized logical tree; `physical_plan()` displays the resulting physical tree. Planning does not collect the table.

Sources are DataFusion table providers. Ordinary row projection, filtering, and top-level explode use logical Projection, Filter, and Unnest nodes. Union is a partition-sensitive extension with optimized logical children; it aligns branches using DataFusion projections and preserves their execution partition sequence. Globals are singleton relations bound with logical cross joins. Scalar operations use native DataFusion expressions where semantics agree; remaining expression kernels are explicit scalar UDFs. Their identities must distinguish their programs so optimizer common-expression elimination cannot merge different operations.

Ordinary grouped and total aggregation use logical Aggregate nodes with existing aggregate UDFs. Filtered/exploded aggregate scopes use logical filters, unnest, and joins. Canonical key expressions preserve Vail equality for grouping; an ordered-partition extension supplies ordered input for collect/take. Aggregate initialization that depends on expressions and nested fold/group aggregation currently require specialized extensions.

`_same` builds a comparison action extension with both ordered row-input logical trees, optimized together.

Partition-sensitive operations are explicit logical extension nodes with child logical plans. DataFusion optimizes and physically plans these children before the extension constructs its implementation. Stable key ordering, interval-cover joins, partition mapping, and partition-preserving head/tail require semantics beyond an ordinary unordered SQL relation. These extensions reuse DataFusion execution operators; they do not replan their original unoptimized child TableIR trees. Row globals, output globals, and external expression bindings are explicit logical inputs to extensions, so their dependencies are optimized too. Expression-backed sources evaluate their initial Arrow array only when execution first pulls a partition, share that evaluation across the action, and reset it for the next action.

The Viceberg provider retains residual filters and uses certified key bounds for supported predicates to prune files. Float metrics pruning is conservative because Iceberg's NaN assumptions differ from Vail totalOrder. File pruning and Vortex row-level predicate pushdown are distinct capabilities; the latter requires additional reader plumbing. See [comparison audit](VORTEX_COMPARISON_AUDIT.md).

A selected repartition output is a physical optimization boundary: its internal DataFusion range/round-robin repartition and selected output index are coupled. Rewriting the partition map independently would change which rows belong to the selected Vail partition. The child logical pipeline is optimized before constructing this boundary. Plans reset state between repeated actions and metadata prepasses.

Checked expressions retain filter sequencing. DF55's physical filter-pushdown rewrite can inline volatile projection expressions and evaluate a failing cast on discarded rows. For a tree containing volatile expressions, Vail omits those physical rewrite rules. The logical optimizer and certified source-file pruning still run. The regression covers an excluded malformed value and an error on a surviving malformed value.
