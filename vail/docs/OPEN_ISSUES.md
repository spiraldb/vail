# Issues to resolve

- **Range/list-mean throughput:** Controlled 10M-row profiling corrected the earlier `array_avg` conclusion: direct DataFusion average took 6.286s / 65.81 core-seconds versus the composed mean's 10.942s / 105.20 core-seconds. Most sampled CPU was range construction, numeric cast buffers, and zeroing, rather than reduction. Typed Int32 range and direct numeric-buffer mean DataFusion UDFs are being implemented to remove these casts and intermediate child arrays; retain benchmark evidence in `conformance/runs/20261014-range-means-profile/`. This still materializes ranges; implicit sequences/fused reductions remain a possible optimization. Coordinate-wise aggregates reuse DataFusion aggregate states; complex composed array-aggregation bodies still use the general relational path.

- **Text interoperability parity:** Add Hail float and nested JSON text rendering, type imputation, regex delimiters, compressed/BGZF and remote sources, source byte-range partitioning, parallel text export and types files, and typed expression-level JSON parsing. Keep imports as lazy DataFusion scans and exports as streaming DataFusion sinks. See [Text import and export](TEXT_IMPORT_EXPORT.md).

- **Streaming head planning:** Partition-preserving `Table.head` currently counts partitions whose row counts are unknown before selecting them. Avoid those preliminary reads while retaining Hail's partition behavior. Text header discovery uses a separate bounded DataFusion prefix-sampling action and does not perform these counts.

- **Lookup fragment covering:** Keyed lookup currently replays the ordered target plan for each querying partition. Use probe key bounds to plan a covering of overlapping target fragments, preserving independent source partitions and avoiding unnecessary target scans. See [Table lookup](TABLE_LOOKUP.md). Extend lookup to all matches, interval containment, and collection-lambda correlation.

- **Missing type operations:** Implement the dictionary, set, tuple, ndarray, string, and collection APIs tracked in [Missing type operations](MISSING_TYPE_OPERATIONS.md), including the partial implementations whose return types or accepted inputs still differ from Hail.
- **`approximate_quantiles._compaction_counts`:** Determine how to expose Hail-compatible KLL compaction counts. The current KLL dependency does not provide the required counts, so this may require a KLL reimplementation.
- **Reference sequence and liftover:** Coordinate-only reference genomes and Locus types are implemented. Implement the bounded streaming FASTA-to-Viceberg importer, explicit sequence bindings, sequence context, and liftover described in [REFERENCE_GENOMES.md](REFERENCE_GENOMES.md). The prepared GRCh38 fixture is available; sequence-dependent APIs currently raise `NotImplementedError`.
- **Aggregator numerical parity:** Investigate numerical edge cases against the pinned Hail runtime and add differential regression tests. In particular, approximate quantiles currently reject `int64` observations outside ±2^53 because the sketch stores doubles; find a library representation that preserves integer ordering and values. Also measure `linreg` accuracy for nearly dependent or badly scaled predictors, since the current normal-equations implementation may lose precision; evaluate library QR/SVD alternatives and Hail's behavior for singular systems before choosing a fix.

- **Non-positive array/stream grouped sizes:** `array.grouped(0)` currently fails during evaluation with DataFusion's zero-step range error, while `array.grouped(-1)` evaluates to an empty array. Confirm the pinned Hail runtime's behavior for both values, then validate size consistently if needed.

- **String rendering of unordered collections:** `hl.str` exports Hail-shaped JSON for sets and dictionaries, but preserves Vail's physical iteration order. Byte-for-byte parity with Scala hash-collection iteration is not implemented; investigate whether to replicate that order or explicitly choose a canonical display order.

- **Complete Arrow data transport migration:** `parallelize`, collection, scalar evaluation, pandas conversion, and text-header sampling now use Arrow IPC. Expression IR still embeds literal data in JSON, and calculated partition bounds retain a JSON data path. Replace these remaining boundaries with typed Arrow inputs/results; JSON is not an approved data format. See [Python data transport](ARROW_PYTHON_BRIDGE.md).

- **Whole-row missingness in expression sources:** Hail `Table.parallelize` can retain a missing struct element and return `None` when collecting it. Vail currently rejects those elements at action time; add a representation for row validity and propagate it through TableIR/DataFusion transformations without confusing a missing row with a present all-null struct. A missing input array must continue to error.

- **Interval filter pushdown through transformations:** `filter_intervals` prunes certified fragments on direct reads with full-key intervals. Filters on transformed tables and exclusion filters currently lower to DataFusion predicates without reader pushdown; key-prefix reads overselect fragments and apply the exact predicate. Propagate intervals through key-preserving TableIR nodes and add prefix-aware fragment pruning.

- **Expression-valued dictionary keys:** Python expressions now have identity hashing, matching Hail, so arrays/struct expressions can be keys in frontend Python dictionaries. Dictionary conversion must recognize expression-valued keys (including nested expressions) and apply value-based duplicate resolution after evaluation; the existing concrete-literal path instead errors with `keywords must be strings`. Object identity must never determine native dictionary key uniqueness. Three original Table assertion bodies were rerun and advance past the hashing failure to this conversion failure. See [results](../conformance/runs/20261002-expression-identity-hash/summary.json).

- **Iceberg float predicate pruning versus IEEE totalOrder:** A Vortex file containing a positive NaN is dropped by Iceberg `plan_files` for `x > +infinity`, even though Vortex and Vail row comparisons match it. Fix or conservatively bypass NaN assumptions in Iceberg metrics pruning before enabling ordinary float predicate pushdown. A residual filter cannot recover skipped files. Implement the decided Vortex-compatible nested missing-first ordering with a versioned comparator and rebuilt bounds; decide on canonical representations of logical collection/special types. See [comparison audit](VORTEX_COMPARISON_AUDIT.md) and its 11 reproducible tests.

- **Call extension registration:** Call storage now uses Hail's packed signed Int32 word in a one-field Arrow struct, with versioned logical-type metadata. Construction and accessors lower through DataFusion arithmetic and array kernels; VCF, genomic aggregates, and Arrow/storage localization consume the packed word. Investigate a registered Vortex extension over bare Int32 only if it provides a concrete benefit over the current metadata envelope. Retain ploidy/phasing and 29-bit representation validation.
- **TODO: ndarray shape-first representation:** Store shape before row-major elements so ordinary Vortex struct/list comparison implements shape-first ordering. Update Arrow schemas, ingestion, expression construction, read/write, and Python localization together; test different shapes, empty dimensions, nested missing values, and round trips. Version the representation and fragment comparator as necessary.
- **TODO: HailDict Vortex extension type:** Represent key/value entries with a canonical, sorted-by-key invariant so equality and ordering use Vortex's sequence comparison without repeatedly sorting during comparisons. Enforce the invariant at construction and transformations, resolve duplicate keys with the intended Hail semantics, and retain missing-key support. Share canonicalization with sets and support nested values and IEEE float keys.
- **TODO: share set implementation with canonical maps:** Model a set as a canonical map from each member to a `Null` value, reusing HailDict ordering/uniqueness infrastructure. Ordinary Vortex Map prohibits missing keys, while Hail sets may contain a missing member; retain that through the HailDict extension storage (or an explicit nullable-key encoding), rather than dropping missing members. Verify `Null`-valued map conversion and comparison kernels, and round trips. This is a proposed representation, not yet implemented.

- **DataFusion physical filter pushdown and checked expressions:** DF55 can inline a volatile cast from a projection and combine it with an earlier filter, evaluating invalid values that Hail would already have discarded. Vail omits the physical `FilterPushdown` rules for logical trees containing volatile expressions; logical predicate/file pushdown remains enabled. Fix or upstream the volatility handling so safe physical pushdown can remain active around such expressions. Reproduced by `test_checked_cast_respects_preceding_filter` in the logical planning tests.

- **Share computed globals across custom partition extensions:** Some specialized partition operations bind the same prepared singleton globals plan separately in each partition. Share its action-local evaluation to avoid repeating expensive deterministic global aggregates; preserve lazy execution and reset between actions. Ordinary logical globals joins already use a shared singleton relation.

- **Native DataFusion empty-struct group emission:** The direct DataFusion 55/Arrow 59.2 probe panics while emitting a zero-field struct grouping key (`dictionary re-encode during emit`). A constant bool physical field, with the empty logical type preserved through versioned Arrow metadata, passes the same comparisons/grouping/sort/join probe. Account for this before removing Vail's canonical-key workaround for empty structs. See [DataFusion ordering audit](DATAFUSION_ORDERING_AUDIT.md).
- **Replace redundant canonical comparison keys:** Use native DataFusion operators for supported physical representations, including floating-point values. Do not introduce float wrappers or a custom equality policy. Packed Calls require coordinated ingestion, accessors, metadata, and roundtrip validation. Set/Dictionary ordering and keying remain unsupported; ndarray work is deferred. Retain versioned storage bounds and handle the native empty-struct grouping limitation separately. See [current differences](INTENTIONAL_HAIL_DIVERGENCES.md).
