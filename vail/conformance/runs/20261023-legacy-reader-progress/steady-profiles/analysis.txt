Findings:
1. Full decode hot code includes Node::append_list, append_struct,
   try_append_varint_run, scalar varint continuation handling and Zstd.
   append_list includes inlined parsing/building; its name does not establish
   that Arrow's append methods are intrinsically slow.
2. Actual DataFusion file-source BaselineMetrics asks
   get_record_batch_memory_size -> List.to_data -> Struct.to_data ->
   LazyArrowCall.to_data. Thus accounting expanded calls despite storage-level
   lazy export. A new buffer visitor preserves exact allocation deduplication
   without materializing values, covered through actual DataFusion accounting.
3. DP sum samples include struct dispatch, varint runs, skip_varints and
   skip_array. Unreferenced GT is skipped without allele decomposition.
4. Scalar field decisions include projection, requiredness, append kind,
   run eligibility and special struct postprocessing; these are known per
   reader. Missing bits and varint terminators depend on input bytes.

Changes under validation:
- Memory accounting visits retained buffers without materializing calls.
- Select struct element decoding outside list element loop; precompute struct
  postprocessing; one dense-record missingness guard.
- Skipped varints count terminators using word masks/popcount without decoding
  or validating numeric widths. Bounds, exact cursor position and EOF remain.
