## Important source compatibility gaps — raw merge is NOT automatically equivalent

DF55scalar AvgAccumulator::evaluate returns missing whenever count==0, regardless of retained sum. Mean wrapper normalizes it toNaN. Native groups evaluate divides sum/count for a group marked valid: count0 plus finite residual/Inf can produceInf instead ofNaN. This is a real API semantic boundary for retracted or arbitrary schema-valid states, not permission to change native AVG. Also count>0 with a null sum gives scalar missing→NaN while native group may mark the count valid and divide initial0→0. Thus blindly mapping all state rows to groups is invalid.

Proof candidate: classify a mean snapshot as contributing only when OUTERstate valid AND count defined AND count>0 AND sum defined. Excluded rows mean empty/undefined scalar result and must produce existing mean NaN through the existing MeanGroups wrapper's empty-group result; never merge their hidden sum payload. Use existing Arrow validity/comparison/selection kernels, not custom mean math. Nonfinite defined sums at positive counts remain contributing and preserve nativeNaN/Inf arithmetic. These checks are data-dependent, selected once per bounded batch/chunk with typed count/sum descriptors, not factories per row. If this policy or metadata/state format is not actually equivalent under public API tests, stop no code.

Each visible state row maps to a DISTINCT group, exactly one complete snapshot contribution. Do NOT use this to combine several partial states into one group: scalar one-row merge and grouped repeated contributions can have different floating reduction order. Original partial merge semantics happen upstream untouched. No array ofFloat64values is being averaged here; already-computed count/sum snapshots are finalized. Keep negative zero and nonfinite classes in the proof. UInt64count and Float64sum are the only admitted physical state fields, with exact prepared descriptors; any unsupported physical/logical type/layout keeps old finalizer.

## Lifecycle and concurrency barrier to resolve before implementation

EmitTo::All calls mem::take on native counts/sums (DF55groups_accumulator.rs42). This empties the mutable groups and transfers/drops backing storage; it does NOT promise reusable capacity. A reusable native object can avoid repeated factory/field setup while still allocating native vectors per chunk. Do not claim storage reuse that the API does not provide or alter DF internals. Public repeated-cycle tests must prove no stale groups/null validity after All.

FinishState currently takes &self on a cloned immutable descriptor used in nested callbacks. A single Arc<Mutex<groups>> per query would serialize unrelated workers and is not an approved solution; a generic global/threadlocal pool is outside scope. Before code, locate a worker/execution-local finalization workspace owned outside both outer state-row and child coordinate loops. Query preparation chooses descriptor/factory once, worker initialization creates mutable native groups once, subsequent chunks only merge/evaluate/reset. If the current scalar-UDF lifetime API cannot provide that without a new framework or row/batch factory churn, this is a **no-code exit**. Instantiating one groups accumulator inside child.finish_states for every outer prefix row does not satisfy the standing setup requirement.

Proposed bounded worker policy remains preliminary: chunk<=1024state rows AND256KiB visible primitive state input; compact visible selected indices into reusable bounded buffers before library merge, never excluded-envelope gathers. Native groups get chunk-local DISTINCT output IDs; scatter/restore chunk results through library selection without changing row order. Excluded rows remain empty meanNaN. Worker retained storage cap1MiB including actual size()/capacity/padding/owner overhead; oversize/unsupported state uses old route unless a separately reviewed safe temporary policy exists. Original input states, indexed snapshots, output ownership and partition×aggregate worker concurrency remain separately live. Result chunk concatenation and EmitToAll vector churn count toward resource gates. No global RAM cap or net memory improvement claim.
