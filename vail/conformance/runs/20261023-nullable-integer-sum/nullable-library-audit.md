arrow-arith src/aggregate.rs public sum<T>(&PrimitiveArray<T>) -> Option<T::Native> uses its optimized nullable lanes/word validity path but cannot choose a wider accumulator. sum_array<T,A> has the same result width and downcasts ordinary inputs to PrimitiveArray<T>; its ArrayAccessor parameter does not expose a general widening reducer. NumericAccumulator and aggregate_nullable_lanes are private. sum_checked changes overflow policy, not width. The same-width kernel can be reused after combining logical nulls with Arrow NullBuffer::union_many, constructing a zero-copy PrimitiveArray header and slicing by list offsets.

DataFusion functions-nested55.0.0 array_sum returns Float64 and coerces list children to Float64; this loses large integer exactness and makes empty/all-null rows null rather than Hail's typed zero. It cannot replace exact integer sums. DataFusion SUM accumulator uses Arrow's same-width sum after numeric argument coercion; widening requires a widened physical input array.

Therefore the candidate reuses Arrow for Int64→Int64 and Int32→Int32. The only retained arithmetic adapter is Int32→Int64, consuming Arrow BitChunks and Int32 values without a widened child array. Static primitive width, output width, filter_missing and field offsets are selected once during typed expression lowering into a prepared function pointer. Per-batch downcasts check that incoming Arrow arrays match the prepared type; they do not choose the kernel. Logical null masks remain data-dependent and are merged once per batch.
